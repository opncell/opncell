# 26.7.2_10 candidate

Includes revision 9. Cellular log view, Clear, Download, and the path label now share a log destination resolver. For running daemons, the resolver uses Open5GS -l or MongoDB --logpath arguments. When stopped, it falls back to /var/log/opncell/<daemon>.log or /var/db/mongodb/mongod.log. Open5GS YAML paths on the migration appliance were verified to match these defaults. Download preserves Search, severity and timeframe filters.

The path and timeframe occupy a dedicated toolbar row below Search. MongoDB JSON parsing recognizes its database directory log path.

Installation checks known /var/log/opncore symlinks. Links are removed only when their targets exactly match the old Open5GS install tree and no running command, Open5GS configuration, rc.d script or rc.conf.d file references the legacy directory. A removed-link manifest is stored at /var/db/opncell/legacy-log-links.json. Target files, unknown links and regular files are preserved. This cleanup does not restart services.

Clear truncates the open file without replacing it. A daemon already writing to a file deleted by the older Clear action may require a separate controlled restart; this update does not silently restart it.

Validation: 37 Python tests and 9 PHP sorting/lifecycle checks passed, plus PHP/JavaScript/shell syntax checks. Appliance acceptance remains required for toolbar layout, current MongoDB log contents, Clear followed by new daemon activity, and filtered Download.

Subscribed users count sorting remains outstanding. Public repository activation is separate from this private candidate.
