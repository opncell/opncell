# 26.7.2_18 CPU-routing release

The installer automatically selects AVX2 or NOAVX catalogs using kernel-reported CPU features, probes the candidate before package replacement, verifies the installed binary digest, and persists the selected OPNcell repository after successful installation/database verification. The previous repository file is backed up; other repository configurations are unchanged. Preflight-only mode tests routing and binary compatibility without installing or changing live configuration.

Both catalogs use the same plugin artifact (SHA256 b1c7de598f07c4b88fb13dc6cb57bd37b5c5c07c72d8c4377e8647205bd74e5a) and 49 packages each. The portable route contains Atom-tested MongoDB 8.0.34_3; the AVX2 route contains the exact tested official 8.0.34_1 package. The shared plugin declares a common minimum; the installer requires _3 or newer on NOAVX and permits _1 only for the exact AVX checksum exception. See the migration procedure for details.

Validated: 50 local Python tests, shared package build/file checks, real AVX routing and binary preflight, simulated non-AVX routing and portable-binary preflight on the AVX host, and the preserved FreeBSD 14 catalog (os-cellular 25.8.12_2). MongoDB AVX database/index/restart tests passed earlier; the portable build was tested on the Atom appliance.

Not yet validated: full installer execution on an OPNsense AVX appliance, prepared MongoDB 5-to-8 migration through the updated installer, and hourly log rotation. Public routes were activated on 2026-11-09 after 114 staged HTTP file hashes and CPU/ABI routes passed verification. Both CPU preflights then passed through the stable public URL. The default ABI route remains portable; the CPU-aware installer selects and persists the AVX2 route on eligible hosts. No production service/database/package was changed during these checks. Backup/export preparation remains separate from the install/restore stage.

Live repository: http://repo.opncell.io/OPNcell-repo . Installer bundle: http://repo.opncell.io/OPNcell-repo/installer.tar.gz . The original ABI-based cellular.conf remains unchanged; ordinary pkg commands use the configured route rather than detecting CPU capabilities themselves. No appliance packages or databases were changed by publication.
