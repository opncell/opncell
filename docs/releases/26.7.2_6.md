# OPNcell 26.7.2_6 installation and upgrade playbook

## Release inventory

Target appliance tested in this session is OPNsense 26.7.8_2-amd64 on FreeBSD 15.1 with ZFS. Commands shown for appliance and build-host shells are csh compatible. Run one transfer or interactive package transaction at a time.

| Package | Role |
|---|---|
| os-cellular 26.7.2_6 | Cellular UI, configuration, service actions, subscriber provisioning |
| open5gs 2.8.0_1 | Open5GS 2.8.0 with the FreeBSD freeDiameter basename fix |
| mongodb80 8.0.34_1 | Official FreeBSD 15 amd64 binary, NOAVX enabled |
| opncell-mongosh 2.14.0 | Packaged MongoDB Shell |
| node22 | Runtime dependency of MongoDB Shell |
| Python 3.12, PyYAML, ujson, bash | Plugin runtime dependencies |

All transitive dependencies and exact selected versions are recorded in `packages.lock.json`. The host Python 3.12.13_3 was used only to obtain build metadata. The collector selects a Python runtime of at least 3.12.15. Review the generated vulnerability report because earlier audits reported Python findings, including on 3.12.15.

Known tested package checksums are in `tested-packages.sha256`. The collector verifies them before creating the package repository.

## Public package repository

The bootstrap configuration is served at `http://repo.opncell.io/cellular.conf`.
It points to `http://repo.opncell.io/OPNcell-repo/${ABI}`, with priority 200.
FreeBSD 15 amd64 selects the versioned 26.7.2_6 catalog containing all 48 runtime
packages. FreeBSD 14 amd64 selects the preserved legacy catalog. The catalog routes
were checked separately with simulated FreeBSD 14.3 and 15.1 client databases.
pkg's host ABI remains enforced during normal installation.

Existing clients with the older URL must fetch cellular.conf again and run
`pkg update -f -r OPNcell`. This resolves the mixed-major-ABI catalog error before
retrying the OPNsense firmware update.

The retained FreeBSD 14 catalog contains os-cellular 25.8.12_2 (and 25.8.7),
Open5GS 2.7.6, and MongoDB 5.0.30. Catalog compatibility is verified. These are
historical binaries and do not include the 26.7.2_6 feature work. Their application
behavior on OPNsense 26.1 requires separate acceptance. Preserve an existing newer
plugin rather than forcing a downgrade.

Run the client setup as root on the target OPNsense appliance:

```csh
mkdir -p /usr/local/etc/pkg/repos
fetch -o /usr/local/etc/pkg/repos/OPNcell.conf http://repo.opncell.io/cellular.conf && pkg update
pkg rquery -r OPNcell '%n-%v' os-cellular mongodb80 open5gs opncell-mongosh
```

On a FreeBSD 15 appliance, expect `os-cellular-26.7.2_6`, `mongodb80-8.0.34_1`, `open5gs-2.8.0_1`,
and `opncell-mongosh-2.14.0`. Preview a fresh installation with:

```csh
pkg install -n -r OPNcell os-cellular
```

For an existing installation, complete the backup procedure below and preview:

```csh
pkg upgrade -n -r OPNcell os-cellular mongodb80 open5gs
```

Inspect the transaction before running it without `-n`. Existing MongoDB data paths
and site keys require the same preservation steps as a local-bundle upgrade.

The web-served catalog is staged under
`/usr/local/www/apache24/data/cellular/releases/26.7.2_6/repo`.
The previous repository remains under `releases/26.7/repo`.
Publication changes the `OPNcell-repo` symlink atomically after staging.
Root access is required for that final link replacement.

## Tested behavior and remaining acceptance

On OPNcell-e200-a, upgrades reached MongoDB 8.0.34_1, opncell-mongosh 2.14.0, and os-cellular 26.7.2_6. MongoDB ping succeeded and the subscriber remained present. Subscriber edits and save notices were reported working. The user reported service restart and successful-Apply navigation working after revision 6.

Earlier lab checks exercised 4G and 5G SA local daemon startup, SCTP support, loopback VIP preservation, and Hnet key generation. Standard NSA uses the EPC service set. NRF and SCP remain enabled by the current plugin configuration. Changes to that mapping require checking the SMF configuration first.

The latest single/bulk delete paths have local simulated checks. Explicit appliance delete/failure acceptance, a complete clean installation, a reboot of the final combined bundle, and radio registration/data traffic remain pending. Avoid describing this bundle as five-nines qualified.

## Preserve the build inputs

The source bundle contains the cumulative port overlay, source snapshot, helper scripts, and this playbook. The collected release adds:

- `packages/` with one selected version of each required package and repository metadata.
- `SHA256` and `packages.lock.json` for binary integrity and dependency tracking.
- `collection-report.json` showing source paths.
- `package-audit.txt` with the current vulnerability check.
- `build-inputs/` containing the build-host port recipes and original distfiles.

Retain the original MongoDB Shell distfile. Recreating it with a new npm install can resolve different transitive package versions. Keep the lockfile embedded in the existing distfile. Package builds on the shared host use `NO_DEPENDS=yes` only after staging checks, and explicitly supply dependency records using the packaged runtime manifests. That procedure is suitable for this files-only plugin and must not be generalized to compiled ports.

## Preview installation

Transfer and extract the complete bundle to a persistent staging location on the appliance. Check package hashes from the release directory:

```csh
sh -c 'while read -r expected package; do test "$(sha256 -q "$package")" = "$expected" || exit 1; done < SHA256'
mkdir -p /tmp/opncell-release-repos
printf '%s\n' 'OPNcellRelease: { url: "file:///root/opncell-release/26.7.2_6/packages", enabled: yes }' > /tmp/opncell-release-repos/OPNcellRelease.conf
pkg -o REPOS_DIR=/tmp/opncell-release-repos install -n -r OPNcellRelease os-cellular
```

The example assumes the bundle is at `/root/opncell-release/26.7.2_6`. Set the repository URL to its actual location. Examine proposed changes to existing OPNsense packages, including Node, Python, OpenSSL-related libraries, and curl. Keep the OPNsense repository configuration under normal firmware management.

## Back up an existing appliance

Record the active database command and filesystem before the package transaction:

```csh
ps axww | grep '[m]ongod'
df -h /var/db/mongodb
service mongod onestatus
pkg query -a '%n-%v' | grep -E '^(os-cellular|open5gs|mongodb80|opncell-mongosh|node22|python312)-'
```

An older installation used `/usr/local/bin/data/db`. Obtain the effective database path from the running process and rc settings. The `--dbpath` argument overrides a different `storage.dbPath` in mongodb.conf.

Export the OPNsense configuration through System → Configuration → Backups. Protect copies of Hnet private keys, database archives, and certificate keys as secrets. config.xml alone does not back up MongoDB subscriber data or external private-key files.

For the verified `/var/db/mongodb` layout, create an owner-only cold backup. Temporarily stopping MongoDB interrupts database access:

```csh
umask 077
set mongo_backup = /root/mongodb-before-cellular-26.7.2_6-`date +%Y%m%d-%H%M%S`.tar.gz
service mongod onestop && tar -C / -czpf "$mongo_backup" var/db/mongodb usr/local/etc/mongodb.conf && service mongod onestart
service mongod onestatus
tar -tzf "$mongo_backup" > /dev/null
sha256 "$mongo_backup"
```

Use the actual data path in that archive command on legacy installations. If the archive command fails, MongoDB remains stopped because the commands use `&&`. Resolve the failure and explicitly start it again.

Take a ZFS snapshot or boot environment before upgrading. Confirm which dataset contains each database and configuration directory. A root boot environment does not necessarily capture separate `/var` or `/usr` datasets. Keep the cold archive and previous package versions available for recovery.

## Upgrade

After backup and an accepted preview, apply the targeted plugin upgrade:

```csh
pkg -o REPOS_DIR=/tmp/opncell-release-repos upgrade -n -r OPNcellRelease os-cellular mongodb80 open5gs
```

If MongoDB will be upgraded, stop it before running the accepted transaction:

```csh
service mongod onestop
pkg -o REPOS_DIR=/tmp/opncell-release-repos upgrade -r OPNcellRelease os-cellular mongodb80 open5gs
service mongod onestart
service mongod onestatus
```

Wait for successful package completion before starting the service. A failed transaction requires inspecting the package and service state first.

The plugin's installation hook preserves an existing MongoDB rc script and configuration. Confirm the running daemon still uses the original database path afterward. Preserve site configuration when reviewing any new sample files.

## Fresh installation prerequisites

The tested Open5GS 2.8.0_1 package originally omitted the generated daemon YAML/freeDiameter configuration samples. The working lab received these files and TLS material separately. Therefore the binary bundle requires site configuration preparation before a fresh-install acceptance run.

Prepare all daemon YAML files used by the chosen topology under `/usr/local/etc/open5gs`, the Diameter configuration files under `/usr/local/etc/freeDiameter`, and the CA/certificate/private-key files at the paths referenced in those configurations. Resolve paths against the installed `/usr/local` layout. Use local IPv4 MongoDB URI `mongodb://127.0.0.1:27017/open5gs` for the tested standalone setup.

Hnet private keys belong under `/usr/local/etc/open5gs/hnet`. Do not distribute appliance-generated private keys, real subscriber credentials, MongoDB data, or site config.xml as generic installation defaults.

The prepared sample-staging script can integrate generated defaults into a future Open5GS package using `@sample` entries. That changes the server package and needs its own build and fresh-install validation.

## Post-install checks

```csh
pfctl -s info | grep '^Status:'
sysctl net.inet.sctp.sendspace kern.ipc.maxsockbuf
ifconfig lo0 | grep 'inet 127\.'
configctl template reload OPNsense/OPNCell
service mongod onestatus
/usr/local/bin/mongosh 'mongodb://127.0.0.1:27017/open5gs' --quiet --eval 'print("MongoDB " + db.version()); printjson(db.runCommand({ping: 1})); print("Subscribers: " + db.subscribers.countDocuments({}))'
```

Expect PF enabled, SCTP available, maxsockbuf at least 33554432, preserved intended loopback VIPs, template reload OK, and MongoDB reachable. The hook makes SCTP loading persistent and adds missing plugin VIPs. Verify the installed descriptions against the site backup.

Refresh the browser after upgrading. Apply the intended topology. A successful apply opens Configurations. System Services should show `open5gs-*` names and `mongod`, with MongoDB state matching the rc service status.

| Topology | Signaling listener | Radio-facing GTP-U listener |
|---|---|---|
| 4G / standard NSA | MME site-address:36412/SCTP | SGW-U site-address:2152/UDP |
| 5G SA | AMF site-address:38412/SCTP | UPF site-address:2152/UDP |

For colocated standard NSA, UPF may retain `127.0.0.7:2152` for its gateway-side traffic. SGW-U and UPF require distinct socket bindings. The lab radio-facing address was `100.64.4.1`. Use the actual site interface address.

```csh
sockstat -4l -P sctp
sockstat -4l -P udp | grep 2152
```

Verify add, read, edit, and delete using disposable subscriber data. Check that failed edits retain the form and display the reason. Test duplicate IMSI, validation, and interrupted database access in the isolated lab. Reopen edited records to verify persistence. Confirm Hnet key paths and the selected topology after transitions. Finally reboot and repeat the database, service, VIP, and listener checks.

## Recovery

If MongoDB cannot start, inspect its rc settings and log before changing the database path. Restore binary and data versions as a matched set when required. Stop MongoDB before restoring the cold archive. Preserve the failed data directory separately and verify archive contents and ownership before extraction.

If service controls report a failure, compare configd output, rc status, and the daemon log. The revision 6 controller normalizes configd responses and checks the resulting service state. Logs are under `/var/log/configd/latest.log` and `/var/log/opncell/`.

Keep the release lock, package audit, accepted transaction preview, and test results with each appliance deployment.
